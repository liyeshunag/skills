# YAML 测试用例结构

生成 Web 自动化测试用例时必须使用以下结构。

## 必填字段

每条测试用例必须包含以下字段，并按这个顺序输出：

1. `测试用例序号`
2. `模块`
3. `测试点`
4. `测试用例标题`
5. `优先级`
6. `操作步骤`
7. `预期结果`
8. `最终结果`
9. `测试人`

## 字段规则

- `测试用例序号`：使用 `testcase_001`、`testcase_002`、`testcase_003`；必须从已有最大编号继续递增，不允许跳号。
- `模块`：使用功能模块、页面、路由或业务域名称。
- `测试点`：描述具体验证行为或校验点。
- `测试用例标题`：简短、清楚、易读。
- `优先级`：只能使用 `P0`、`P1`、`P2`、`P3`。
- `操作步骤`：使用 Codex 或 Web 自动化 Agent 能执行的简洁自然语言步骤。
- `预期结果`：写成明确断言，不能写成泛泛描述。
- `最终结果`：生成但未执行时使用 `未执行`；只有真实执行后才能更新为 `通过` 或 `失败`。
- `测试人`：默认使用 `Codex`，除非用户指定其他测试人。

## 从 web 元素生成步骤

生成 `操作步骤` 时优先使用仓库 `web/` 目录中的真实页面元素：

- 路由：来自 `web/src/app`、`web/src/pages` 或路由配置。
- 按钮：来自 button 文案、组件 props、图标按钮旁边的文字、aria-label。
- 表单字段：来自 label、placeholder、name、schema、动态表单配置。
- 弹窗：来自 modal/dialog 标题、确认/取消按钮文案。
- 列表和状态：来自状态标签、空态文案、loading 文案、toast 文案。
- 下载/预览/编辑：来自页面上真实存在的按钮或菜单项。

示例：

- 如果代码里有 `创建任务` 按钮，步骤写 `点击创建任务`。
- 如果代码里有 `任务分析` 按钮，步骤写 `点击任务分析`。
- 如果代码里有 `附属资料` 弹窗，步骤写 `点击附属资料按钮`，预期写 `弹窗标题展示附属资料`。
- 如果代码只显示图标但有 tooltip 或 aria-label，步骤优先使用 tooltip/aria-label 的文本。

不要使用仓库里不存在的按钮名、页面名、字段名或断言文案。

## YAML 示例

```yaml
testcases:
- 测试用例序号: testcase_001
  模块: 登录
  测试点: 用户使用正确账号密码登录
  测试用例标题: 正确账号密码登录成功
  优先级: P0
  操作步骤:
  - 打开测试网址，测试网址从 TEST_BASE_URL 获取
  - 输入测试账号，测试账号从 TEST_USERNAME 获取
  - 输入测试密码，测试密码从 TEST_PASSWORD 获取
  - 点击登录按钮
  预期结果:
  - 页面跳转到首页或工作台
  - 页面展示当前登录用户信息
  - 不出现登录失败提示
  最终结果: 未执行
  测试人: Codex
```

## 编号规则

生成新用例前：

1. 搜索已有 YAML 测试用例。
2. 提取所有符合 `testcase_[0-9]+` 的编号。
3. 找出最大编号。
4. 新用例从下一个编号开始，至少使用三位数字补零。

如果已有编号为 `testcase_001` 到 `testcase_018`，新用例必须从 `testcase_019` 开始。
