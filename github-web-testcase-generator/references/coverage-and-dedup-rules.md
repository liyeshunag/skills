# 覆盖和去重规则

## 模式选择

用户说 `冒烟`、`主流程`、`核心流程`、`smoke`、`happy path` 或 `main flow` 时，使用冒烟测试模式。

用户说 `全量`、`完整`、`全面`、`full`、`complete` 或 `comprehensive` 时，使用全量测试模式。

如果请求没有明确说明模式，先问一个简短澄清问题。

## 必须覆盖的场景类型

每次生成批次，无论冒烟测试还是全量测试，只要受影响范围允许，都至少覆盖以下场景：

- 正向场景：合法输入、合法权限、成功提交、正确跳转、成功状态流转。
- 反向场景：非法输入、禁止操作、接口失败、错误状态、无权限角色。
- 为空场景：必填项为空、搜索/筛选为空、列表为空、无结果、可选数据缺失。
- 边界值场景：最小/最大长度、数字上下限、日期边界、分页边界、上传大小边界。
- 极端场景：超长文本、快速重复点击、大数据列表、登录态过期、网络超时、并发状态变化。

如果代码没有表单或数值输入，把边界值和极端场景映射到导航、列表数量、分页、鉴权/session、异步状态或接口响应限制。

## 冒烟测试模式

只生成高价值 P0/P1 用例：

- 相关时包含登录、鉴权或入口流程。
- 覆盖 PR 影响的核心创建、查看、编辑、删除或提交流程。
- 覆盖关键路由导航和页面渲染。
- 覆盖关键权限、支付、删除、提交或状态流转。
- 每个核心受影响模块至少有一条正向主流程。
- 对高风险行为补充必要的反向、为空、边界值和极端场景。

冒烟测试不要生成低价值视觉排列、重复字段排列或穷举组合。

## 全量测试模式

覆盖所有受影响行为：

- 页面、路由、tab、弹窗、抽屉、表单、表格、筛选、搜索、排序、分页、上传、下载。
- 按钮、链接、菜单项、禁用态、确认弹窗、取消路径和重试路径。
- 成功、校验失败、服务失败、超时、空响应、部分数据和权限失败。
- 角色/权限分支、feature flag、状态流转和错误恢复。
- 字段级必填、可选、格式、最小值、最大值、边界值和极端值。

输出时优先按模块分组，再按业务优先级和场景类型排序。

## 从 web 元素确定覆盖面

扫描 `web/` 时，把以下元素转成测试覆盖点：

- 路由文件：生成页面可访问、鉴权、跳转、空态和错误态用例。
- 页面组件：生成页面主内容、核心按钮、主要流程用例。
- 表单组件：生成必填、为空、格式错误、边界值、提交成功、提交失败用例。
- 弹窗/抽屉：生成打开、关闭、确认、取消、异常提示用例。
- 列表/表格：生成加载、空列表、分页、筛选、排序、操作按钮用例。
- 状态组件：生成队列中、生成中、已完成、失败、重试、取消等状态流转用例。
- 下载/预览/编辑组件：生成资源可见、预览、下载、下载失败、权限不足用例。
- toast/error 文案：生成错误提示和反向断言。

自然语言步骤和预期结果必须尽量使用这些元素的真实文案。

## 去重规则

即使用词不同，只要已有用例覆盖同一用户可观察行为，就视为重复。

比较维度：

- `模块`
- `测试点`
- `测试用例标题`
- `操作步骤`
- `预期结果`
- 场景类型
- 涉及的路由、页面、组件、按钮、表单、API、权限或状态流转

重复用例必须跳过，只生成新的或缺失的覆盖。

## 优先级规则

- `P0`：登录、核心业务流程、破坏性操作、支付、安全、权限、数据损坏风险。
- `P1`：常用用户流程、必填校验、重要错误路径、主要状态变化。
- `P2`：次要流程、低频校验、可选配置、非关键 UI 状态。
- `P3`：罕见边界、低风险样式行为、探索性长尾覆盖。
