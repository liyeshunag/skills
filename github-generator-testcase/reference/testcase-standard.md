# 测试用例编写规范

## 一、总则

本规范定义了 `github-generator-testcase` Skill 生成测试用例的编写标准。所有自动生成的测试用例必须严格遵循本规范。

## 二、CSV 格式规范

### 2.1 文件命名

```
<ProjectName>_TestCases.csv
```

示例：
- `Helix_TestCases.csv`
- `MedAI_TestCases.csv`
- `DataPlatform_TestCases.csv`

### 2.2 编码格式

- 编码：UTF-8 with BOM
- 换行符：LF (Unix)
- 分隔符：逗号 (,)
- 引用符：双引号 (")

### 2.3 固定字段（不可修改）

| 序号 | 字段名 | 必填 | 说明 |
|------|--------|------|------|
| 1 | 测试用例序号 | 是 | 唯一编号，格式 testcase_NNN |
| 2 | 模块 | 是 | 功能模块名称 |
| 3 | 测试点 | 是 | 测试场景分类 |
| 4 | 测试用例标题 | 是 | 简洁明确的业务标题 |
| 5 | 优先级 | 是 | P0/P1/P2/P3 |
| 6 | 操作步骤 | 是 | 编号步骤，换行分隔 |
| 7 | 预期结果 | 是 | 具体明确的预期结果 |
| 8 | 最终结果 | 否 | 执行后填写 |
| 9 | 备注 | 否 | 附加说明 |
| 10 | 测试人 | 否 | 执行测试的人员 |

## 三、编号规范

### 3.1 编号格式

```
testcase_001
testcase_002
testcase_003
...
testcase_NNN
```

### 3.2 编号规则

1. 连续递增：不允许跳号
2. 全局唯一：同一项目中不重复
3. 增量续编：新生成用例继续上次编号递增
4. 不可重用：已废弃的编号不复用

### 3.3 编号管理

编号由 `testcase_id_manager.py` 统一管理，通过 `testcase-history.json` 持久化。

```json
{
  "current_index": 235,
  "project_name": "Helix"
}
```

下次生成时从 testcase_236 开始编号。

## 四、标题规范

### 4.1 合格标题示例

```
✅ 登录成功
✅ 登录密码错误
✅ 上传PDF成功
✅ 删除文章失败提示
✅ AI生成论文超时
✅ 空文件上传提示
✅ 特殊字符用户名注册失败
```

### 4.2 不合格标题示例

```
❌ 测试登录               （无意义）
❌ 功能验证               （太通用）
❌ 登录                   （不完整）
❌ 测试登录功能是否正常      （冗余）
❌ Login Test            （非中文）
```

### 4.3 标题要求

- 中文书写
- 8-25 个字符
- 包含操作+结果
- 一眼能理解测试内容
- 符合业务语义

## 五、操作步骤规范

### 5.1 格式要求

- 每步一个编号（1, 2, 3...）
- 步骤间用换行符（\n）分隔
- 每步 5-20 个字符
- 动作动词开头

### 5.2 示例

```
1 打开登录页
2 输入用户名"admin"
3 输入密码"Test@123"
4 点击登录按钮
5 查看页面跳转
```

### 5.3 禁止

- 大段文字描述
- 包含预期结果（预期结果有独立字段）
- 模糊表述（如"做相应操作"）
- 超过 10 个步骤（需拆分用例）

## 六、预期结果规范

### 6.1 格式要求

- 分点描述，每点一行
- 包含具体数值、文字、状态
- 覆盖前端/后端/数据库

### 6.2 示例

```
✅ 页面跳转至首页，URL 变为 /dashboard
✅ 顶部显示"欢迎, admin"
✅ 接口 POST /api/login 返回 200
✅ Response Body 包含 token 字段
✅ LocalStorage 写入 auth_token
✅ 数据库 user_login_log 表新增一条记录
```

### 6.3 禁止

```
❌ 正常
❌ 成功
❌ 正确
❌ 功能正常
❌ 无异常
```

## 七、优先级定义

| 优先级 | 定义 | 示例场景 |
|--------|------|---------|
| P0 | 核心功能，阻塞性问题 | 登录失败、支付异常、数据丢失 |
| P1 | 重要功能，影响主流程 | 权限错误、接口超时、数据错误 |
| P2 | 一般功能，影响体验 | 提示不友好、样式错误 |
| P3 | 边缘场景，低概率 | 极端分辨率、特殊字符 |

## 八、测试场景覆盖要求

每个功能点至少覆盖以下 25 类场景：

| 序号 | 场景分类 | 说明 |
|------|---------|------|
| 1 | 正向功能 | 基本功能正常流程 |
| 2 | 反向功能 | 异常输入/错误操作 |
| 3 | 空值测试 | 必填项为空 |
| 4 | Null 值 | 字段值为 null |
| 5 | 边界值 | 临界值（0, 1, max, max+1） |
| 6 | 最大长度 | 输入框最大字符数 |
| 7 | 最小长度 | 输入框最小字符数 |
| 8 | 特殊字符 | <>'"&/\| 等 |
| 9 | SQL 注入 | ' OR '1'='1 等 |
| 10 | XSS | \<script\>alert(1)\</script\> |
| 11 | 权限 | 无权限/越权操作 |
| 12 | 重复提交 | 快速双击/多次点击 |
| 13 | 并发 | 多人同时操作 |
| 14 | 网络异常 | 断网/弱网 |
| 15 | 超时 | 接口超时处理 |
| 16 | 浏览器兼容 | Chrome/Firefox/Safari/Edge |
| 17 | 分辨率 | 1920x1080 / 1366x768 / 375x667 |
| 18 | 国际化 | 中英文切换 |
| 19 | 文件格式 | 支持/不支持的文件格式 |
| 20 | 文件大小 | 超大文件/空文件 |
| 21 | AI异常返回 | AI 返回格式错误/内容异常 |
| 22 | 服务重启 | 操作过程中服务重启 |
| 23 | Token失效 | Token 过期后的行为 |
| 24 | Session过期 | Session 超时后的行为 |
| 25 | 回归测试 | 修改后关联功能正常 |

## 九、模块命名规范

### 9.1 模块划分

- 按功能模块划分，不按技术分层
- 模块名 2-6 个中文字符
- 示例：登录、注册、用户管理、文章管理、AI生成

### 9.2 测试点命名

- 使用上述 25 类场景名称
- 或具体业务场景名
- 示例：正向功能、边界值测试、权限验证、并发测试

## 十、质量检查清单

生成测试用例后，自动检查：

- [ ] 所有必填字段已填写
- [ ] 编号连续无跳号
- [ ] 编号无重复
- [ ] 标题符合规范（8-25字符，中文）
- [ ] 操作步骤分步清晰
- [ ] 预期结果具体明确
- [ ] 无"正常/成功/正确"等模糊词汇
- [ ] 覆盖至少 25 类场景
- [ ] CSV 编码为 UTF-8 BOM
- [ ] 无重复用例（标题/步骤相同）
