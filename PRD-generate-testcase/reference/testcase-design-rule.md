# 测试用例设计规则

## 一、设计方法论

### 1.1 等价类划分法 (Equivalence Partitioning)

将输入域划分为若干等价类，每个等价类中的数据对程序的测试效果等价。

**有效等价类**：符合需求定义的、有意义的输入数据集合。
**无效等价类**：不符合需求定义的、无意义的输入数据集合。

**应用场景：**

- 输入框（文本、数字、日期）
- 下拉选择
- 文件上传（类型、大小）

**设计要点：**

- 每个等价类至少设计 1 个用例
- 有效等价类尽量多覆盖，确保主要路径贯通
- 无效等价类逐一覆盖

**示例：手机号输入**

| 等价类 | 用例示例 |
|-------|---------|
| 有效：11 位中国大陆手机号 | 输入 13800138000，校验通过 |
| 无效：位数不足 | 输入 1380013，提示格式错误 |
| 无效：位数超出 | 输入 138001380001，提示格式错误 |
| 无效：非数字字符 | 输入 1380013800a，提示格式错误 |
| 无效：空值 | 不输入，提交时提示必填 |

### 1.2 边界值分析法 (Boundary Value Analysis)

在等价类边界上设计测试用例，因为边界是最容易出错的地方。

**设计要点：**

- 边界值本身
- 边界值 +1
- 边界值 -1
- 最小值 -1
- 最大值 +1

**示例：用户名长度限制 2-20 个字符**

| 输入长度 | 用例 | 预期 |
|---------|------|------|
| 1 | 输入 1 个字符 | 提示长度不足 |
| 2 | 输入 2 个字符 | 校验通过 |
| 3 | 输入 3 个字符 | 校验通过 |
| 19 | 输入 19 个字符 | 校验通过 |
| 20 | 输入 20 个字符 | 校验通过 |
| 21 | 输入 21 个字符 | 提示长度超出 |

### 1.3 判定表法 (Decision Table)

适用于多个条件组合产生不同结果的场景。

**设计步骤：**

1. 识别所有条件
2. 列出每个条件的取值
3. 列出所有条件组合
4. 简化合并
5. 为每个规则设计 1 个用例

**示例：订单优惠规则**

条件：会员等级（普通/银卡/金卡）、订单金额（<100 / 100-500 / >500）
动作：折扣率（无折扣 / 9 折 / 8 折 / 7 折）

### 1.4 状态迁移法 (State Transition)

适用于有明确状态流转的业务场景。

**设计要点：**

- 覆盖所有合法状态迁移路径
- 覆盖非法状态迁移（从某状态尝试跳转到不该到达的状态）
- 覆盖状态不变的操作

**示例：订单状态流转**

```
待支付 → 已支付 → 已发货 → 已签收 → 已完成
        ↘ 已取消
              ↘ 已退款
```

### 1.5 场景法 (Scenario-based)

按照用户实际使用路径设计端到端测试流程。

**设计要点：**

- 基本流：用户最常走的完整路径
- 备选流：在某个步骤出现分支后的路径
- 异常流：因错误或异常中断后的路径

## 二、测试用例设计步骤

### Step 1：识别测试对象

从 PRD 中识别需要测试的功能点：

1. 列出所有功能模块
2. 每个功能模块拆解为功能点
3. 每个功能点分析输入、处理、输出

### Step 2：确定测试策略

| 功能类型 | 主要方法 | 补充方法 |
|---------|---------|---------|
| 表单/输入类 | 等价类 + 边界值 | 特殊字符 |
| 业务规则类 | 判定表 + 场景法 | 边界测试 |
| 状态流转类 | 状态迁移 | 场景法 |
| 查询/展示类 | 等价类 | 场景法 + 边界（分页） |
| 接口/数据类 | 等价类 + 边界值 | 异常测试 |

### Step 3：覆盖类型分配

每个功能点至少设计以下类型的用例：

| 覆盖类型 | 最少数量 | 说明 |
|---------|---------|------|
| 正向流程 | ≥1 | 主路径基本流 |
| 反向验证 | ≥1 | 错误输入/权限不足 |
| 空值测试 | 按必填字段数 | 每个必填字段一条 |
| 边界测试 | 按约束条件数 | 每个边界条件上下边界各一条 |
| 异常流程 | ≥1 | 网络/服务异常 |

### Step 4：优先级分配

参照 `priority-rule.md` 为每个用例分配优先级。

## 三、常见场景设计指引

### 3.1 登录/注册模块

必测场景：

- 正确账号密码登录
- 错误密码登录
- 不存在的账号登录
- 账号为空/密码为空
- 记住密码功能
- 验证码相关（正确/错误/过期/刷新）
- 登录状态保持/过期
- 多地登录/踢下线
- 密码输入次数限制/锁定
- 第三方登录（如有）

### 3.2 列表/搜索模块

必测场景：

- 默认列表加载
- 关键词搜索（精确/模糊）
- 组合条件筛选
- 筛选条件重置
- 排序切换
- 分页加载
- 空数据展示
- 加载更多/下拉刷新
- 网络异常时列表展示

### 3.3 表单提交模块

必测场景：

- 全部正确填写提交成功
- 每个必填字段为空提交
- 每个字段输入超长内容
- 每个字段输入特殊字符
- 重复提交防护
- 提交中网络中断
- 提交后返回不重复提交

### 3.4 文件上传模块

必测场景：

- 支持格式上传成功
- 不支持格式上传拦截
- 单个文件大小边界（临界值通过、临界值+1 拦截）
- 批量上传数量边界
- 上传中取消
- 上传中网络中断
- 上传后预览/下载

### 3.5 支付模块

必测场景：

- 正常支付流程
- 余额不足
- 支付密码错误
- 支付超时
- 重复支付防护
- 支付后回调处理
- 退款流程
- 多种支付方式切换

## 四、禁止生成的用例类型

1. **纯描述性用例**：如「验证登录功能是否可用」
2. **含混不清的用例**：如「测试系统正常响应」
3. **非功能性用例**（除非 PRD 明确要求）：如「系统并发 10000 用户」
4. **重复等价类用例**：同一个等价类不重复生成
5. **脱离 PRD 的臆测用例**：PRD 未提及的功能不自行设计
