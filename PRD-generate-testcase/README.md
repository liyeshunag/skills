# PRD-generator-testcase

## Skills 介绍

**PRD-generate-testcase** 是一个面向测试工程师的 Agent Skill，能够根据产品需求文档（PRD）自动分析并生成标准化的测试用例。

### 核心能力

- **多类型输入支持**：支持 PRD 文档、功能设计文档、产品说明、用户故事、原型说明等输入形式
- **全场景覆盖**：自动覆盖正向流程、反向验证、边界测试、空值测试、极端测试、兼容性测试、异常流程 7 大场景
- **智能优先级分配**：基于业务影响自动分配 P0-P4 优先级
- **增量分析**：支持对已有用例进行增量分析，只生成新增/变更功能的用例，避免重复
- **PRD 问题识别**：自动识别 PRD 中的需求缺失、规则不清、流程不完整等问题
- **质量自检**：生成后自动执行格式、内容、覆盖度三维质量检查

### 适用场景

- 📋 需求评审后快速生成测试用例
- 🔄 需求变更后的增量用例更新
- ✅ 测试用例质量审查与覆盖度评估
- 📝 PRD 质量评审辅助

## 输入要求

### 支持的输入格式

| 输入类型 | 格式 | 说明 |
|---------|------|------|
| 产品需求文档 | 文本/Markdown | 包含功能描述、业务规则、用户流程 |
| 功能设计文档 | 文本/Markdown | 详细功能模块设计 |
| 产品说明文档 | 文本/Markdown | 产品功能和使用说明 |
| 用户故事 | 文本 | User Story 格式 |
| 原型说明 | 文本 | 页面流程和交互说明 |

### 输入内容建议

PRD 应尽量包含以下信息，以获得更完整准确的测试用例：

- 产品背景和目标
- 用户角色定义
- 功能模块清单
- 详细的用户操作流程
- 输入字段及校验规则
- 业务规则和约束条件
- 异常情况说明
- 权限控制说明

## 使用方式

### 方式一：直接上传 PRD 文档

1. 准备好 PRD 文档（支持 .md / .txt / .docx 等格式）
2. 将 PRD 内容直接发送，或上传 PRD 文件
3. 说明项目名称（用于文件命名）
4. Skills 将自动分析并生成测试用例

**示例：**

```
请帮我分析以下PRD，生成测试用例：

项目名称：AI医疗助手

[粘贴PRD内容或上传文件]
```

### 方式二：增量更新已有用例

1. 准备好新的 PRD 变更内容
2. 同时提供已有测试用例 CSV 文件
3. Skills 将对比分析，只生成新增/变更的用例

**示例：**

```
请基于以下需求变更，增量更新测试用例：

项目名称：AI医疗助手

原有测试用例：[上传已有CSV文件]

需求变更内容：
[粘贴变更内容]
```

### 方式三：仅进行 PRD 质量评审

1. 直接上传 PRD 文档
2. 说明只需要 PRD 问题识别
3. Skills 将只输出问题清单

**示例：**

```
请对以下PRD进行质量评审，识别存在的问题：

[粘贴PRD内容]
```

## 输出说明

### 输出物 1：测试用例 CSV 文件

文件命名：`{项目名称}_testcase.csv`

包含 10 个标准字段：

| 字段 | 说明 | 
|-----|------|
| 测试用例序号 | 唯一编号，格式 tc_001 |
| 模块 | 功能模块名称 |
| 测试点 | 具体测试的功能点 |
| 测试用例标题 | 简洁明确的用例标题 |
| 优先级 | P0/P1/P2/P3/P4 |
| 操作步骤 | 有序可执行的操作步骤 |
| 预期结果 | 明确可验证的预期结果 |
| 最终结果 | 执行后填写（生成时留空） |
| 备注 | 补充说明 |
| 测试人 | 执行人（生成时留空） |

### 输出物 2：PRD 问题清单（按需输出）

如果 PRD 存在缺失项，将输出问题清单：

| 问题编号 | 问题描述 | 影响 | 建议确认 |
|---------|---------|------|---------|

### 输出物 3：测试覆盖摘要

提供用例统计概览：

- 用例总数
- 优先级分布（P0/P1/P2/P3/P4 数量）
- 覆盖的模块列表
- 质量检查结果

## 常见问题

### Q: 生成的用例编号可以从指定序号开始吗？

A: 可以。如果项目已有用例，在增量模式下手动指定起始编号即可。

### Q: 支持非中文 PRD 吗？

A: 支持。Skill 会适配 PRD 的语言输出对应的测试用例。

### Q: CSV 文件用什么工具打开？

A: 使用 Microsoft Excel、WPS、Google Sheets 或 Numbers 直接打开即可。文件使用 UTF-8 BOM 编码，确保中文正确显示。

### Q: 可以使用脚本校验生成结果吗？

A: 可以。使用 `scripts/testcase-validator.py` 对生成的 CSV 文件进行格式校验：

```bash
python scripts/testcase-validator.py <your_testcase.csv>
```
