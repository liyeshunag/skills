# 测试用例覆盖度检查规则

## 一、覆盖度检查维度

覆盖度检查用于评估生成的测试用例是否全面覆盖了 PRD 中描述的功能需求。

| 维度 | 含义 | 目标覆盖率 |
|-----|------|----------|
| 功能模块覆盖 | PRD 中每个功能模块是否有对应用例 | 100% |
| 功能点覆盖 | 每个功能的具体功能点是否有对应用例 | ≥ 90% |
| 用户角色覆盖 | 每种用户角色是否有对应权限测试 | 100% |
| 业务流程覆盖 | 每条业务流程是否有端到端用例 | 100% |
| 异常场景覆盖 | 关键异常是否有覆盖 | ≥ 80% |
| 测试类型覆盖 | 是否覆盖 7 种测试类型 | ≥ 5 种 |

## 二、功能模块覆盖检查

### 检查方法

1. 从 PRD 中提取所有功能模块列表
2. 统计每个模块在测试用例中出现的次数
3. 识别 0 覆盖模块

### 输出格式

```
功能模块覆盖矩阵:

| 功能模块 | 用例数量 | P0数量 | P1数量 | 覆盖状态 |
|---------|---------|--------|--------|---------|
| 登录模块 | 12      | 1      | 5      | ✅ 已覆盖 |
| 首页    | 5       | 0      | 2      | ✅ 已覆盖 |
| 订单模块| 0       | 0      | 0      | ❌ 未覆盖 |
```

## 三、功能点覆盖检查

### 检查方法

1. 从 PRD 中提取每个功能模块下的具体功能点
2. 匹配测试用例的「测试点」字段
3. 统计已覆盖和未覆盖的功能点

### 功能点粒度

一个功能点对应 PRD 中一个可独立验证的功能描述。

**示例：**

> 登录模块包含：账号密码登录、手机验证码登录、第三方登录、忘记密码

拆解为 4 个功能点：

- 账号密码登录
- 手机验证码登录
- 第三方登录
- 忘记密码

### 输出格式

```
功能点覆盖详情:

【登录模块】
  ✅ 账号密码登录 — tc_001~tc_012
  ❌ 手机验证码登录 — 未覆盖
  ❌ 第三方登录 — 未覆盖
  ⚠️  忘记密码 — 仅 1 个正向用例，缺少异常场景
```

## 四、用户角色/权限覆盖检查

### 检查方法

1. 从 PRD 中提取所有用户角色及其权限
2. 检查是否有针对不同角色的权限测试用例
3. 关键权限点是否有越权测试

### 覆盖矩阵

| 角色 | 权限功能A | 权限功能B | 权限功能C |
|-----|----------|----------|----------|
| 管理员 | ✅ | ✅ | ✅ |
| 普通用户 | ✅ | ✅ | ❌ |
| 游客 | ✅ | ❌ | ❌ |

### 输出格式

```
用户角色覆盖:

| 角色 | 可见功能测试 | 权限越权测试 | 状态 |
|-----|------------|------------|------|
| 管理员 | 3/3       | ✅ 已覆盖   | ✅   |
| 普通用户 | 2/3       | ❌ 未覆盖   | ⚠️   |
| 游客    | 1/3       | ❌ 未覆盖   | ⚠️   |
```

## 五、业务流程覆盖检查

### 检查方法

1. 从 PRD 中提取完整业务流程（用户操作路径）
2. 检查是否存在覆盖完整流程的端到端用例
3. 检查分支流程是否覆盖

### 流程覆盖标准

- **基本流**：必须有完整端到端用例
- **备选流**：每个分支至少 1 个用例
- **异常流**：每种异常中断至少 1 个用例

### 输出格式

```
业务流程覆盖:

【下单流程】
  基本流: 选商品 → 加购物车 → 结算 → 支付 → 完成
    ✅ tc_xxx: 正常下单完整流程

  备选流1: 选商品 → 加购物车 → 修改数量 → 结算 → 支付
    ❌ 未覆盖

  备选流2: 选商品 → 立即购买 → 支付 → 完成
    ✅ tc_xxx: 立即购买流程

  异常流1: 支付超时
    ✅ tc_xxx: 支付超时订单自动取消

  异常流2: 库存不足
    ❌ 未覆盖
```

## 六、测试类型覆盖检查

检查是否覆盖以下 7 种测试类型：

| 测试类型 | 识别规则 | 最低要求 |
|---------|---------|---------|
| 1. 正向功能测试 | 标题描述正常操作成功 | ≥ 1 个/功能点 |
| 2. 反向测试 | 标题含「错误」「非法」「不足」「失败」 | ≥ 1 个/模块 |
| 3. 空值测试 | 标题含「为空」「未选择」「留空」 | ≥ 1 个/必填字段 |
| 4. 边界测试 | 标题含「最大」「最小」「上限」「下限」「边界」 | ≥ 1 个/约束条件 |
| 5. 极端测试 | 标题含「大量」「超长」「高频」「特殊字符」 | ≥ 1 个 |
| 6. 兼容性测试 | 标题含「浏览器」「分辨率」「iOS」「Android」 | 根据 PRD 有则检查 |
| 7. 异常流程测试 | 标题含「网络异常」「超时」「服务异常」 | ≥ 1 个 |

### 输出格式

```
测试类型覆盖:

| 测试类型 | 覆盖状态 | 用例数 | 示例 |
|---------|---------|--------|------|
| 正向功能 | ✅      | 15     | tc_001 |
| 反向测试 | ✅      | 8      | tc_010 |
| 空值测试 | ✅      | 6      | tc_016 |
| 边界测试 | ✅      | 4      | tc_020 |
| 极端测试 | ⚠️      | 1      | tc_025 |
| 兼容性   | ❌      | 0      | -     |
| 异常流程 | ✅      | 3      | tc_030 |

覆盖度: 5/7 (71%)
```

## 七、覆盖度评分

| 等级 | 功能模块覆盖 | 功能点覆盖 | 异常覆盖 | 类型覆盖 |
|-----|------------|----------|---------|---------|
| 优秀 | 100%       | ≥ 95%    | ≥ 90%  | 7/7    |
| 良好 | 100%       | ≥ 85%    | ≥ 70%  | ≥ 5/7  |
| 合格 | ≥ 90%      | ≥ 70%    | ≥ 50%  | ≥ 4/7  |
| 不合格 | < 90%     | < 70%    | < 50%  | < 4/7  |
