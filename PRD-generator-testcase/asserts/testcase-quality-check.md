# 测试用例质量检查规则

## 一、检查总览

质量检查分为三个维度：

| 维度 | 检查项数 | 说明 |
|-----|---------|------|
| 格式检查 | 4 项 | CSV 格式、编码、字段、文件命名 |
| 内容检查 | 6 项 | 编号、重复、空值、优先级、标题、描述 |
| 覆盖检查 | 5 项 | 功能模块、主流程、异常、边界、极端 |

## 二、格式检查

### 检查项 1：CSV 格式正确性

- **检查方式**：使用 CSV 解析器能否正确解析文件
- **通过条件**：无解析错误，行数 = 表头行 + 数据行
- **失败处理**：返回解析错误信息，定位到具体行

### 检查项 2：字段完整性

- **检查方式**：表头字段逐一比对
- **通过条件**：10 个字段齐全，顺序与规范完全一致（测试用例序号、模块、测试点、测试用例标题、优先级、操作步骤、预期结果、最终结果、备注、测试人）
- **失败处理**：列出缺失字段或顺序错误的字段

### 检查项 3：文件命名规范

- **检查方式**：正则匹配
- **通过条件**：匹配 `{非空项目名称}_testcase.csv`
- **失败处理**：提示正确命名格式
- **反例**：`testcase.csv`、`测试用例.csv`、`temp.csv`

### 检查项 4：编码格式

- **检查方式**：检测文件 BOM 标记
- **通过条件**：UTF-8 BOM 编码
- **警告条件**：UTF-8 无 BOM（Excel 可能乱码）

## 三、内容检查

### 检查项 5：用例编号连续性

- **检查方式**：提取所有 tc_id 序号，排序后检查
- **通过条件**：从 001 开始连续递增，无跳号
- **失败处理**：列出跳号位置
- **示例**：tc_001, tc_002, tc_004 → 缺少 tc_003

### 检查项 6：无重复用例

- **检查方式**：按（模块, 测试点, 标题）三元组去重
- **通过条件**：无完全重复的三元组
- **警告条件**：高度相似（编辑距离 < 阈值）
- **失败处理**：列出重复的用例编号

### 检查项 7：必填字段无空值

- **检查方式**：逐行检查 7 个必填字段
- **通过条件**：必填字段（测试用例序号、模块、测试点、测试用例标题、优先级、操作步骤、预期结果）均不为空
- **注意**：「最终结果」「测试人」允许为空
- **失败处理**：列出空字段的用例编号和字段名

### 检查项 8：优先级合法性

- **检查方式**：枚举值校验
- **通过条件**：所有优先级值属于 {P0, P1, P2, P3, P4}
- **失败处理**：列出非法优先级值及所在用例

### 检查项 9：标题简洁性

- **检查方式**：模式匹配
- **模糊词黑名单**：
  - `测试一下.*`
  - `验证.*是否正常`
  - `.*功能测试.*`
  - `.*看看.*`
  - `.*试一下.*`
  - `.*是否可以.*`
- **通过条件**：无模糊词匹配
- **触发后**：标记为警告，建议改进

### 检查项 10：操作步骤可执行性

- **检查方式**：步骤是否包含明确的操作对象和操作动词
- **通过条件**：每个步骤有明确的操作动词（打开、输入、点击、选择、上传等）
- **触发后**：标记为警告，建议改进

## 四、覆盖检查

### 检查项 11：功能模块覆盖

- **检查方式**：列出已覆盖的模块列表
- **通过条件**：PRD 中每个功能模块至少 1 个用例
- **未覆盖**：列出 PRD 中存在但测试用例中未出现的模块

### 检查项 12：主流程覆盖

- **检查方式**：识别正向流程用例（优先级 P0/P1 的正向用例）
- **通过条件**：每个功能模块的主流程至少 1 个正向用例
- **未覆盖**：列出缺乏正向用例的功能模块

### 检查项 13：异常流程覆盖

- **检查方式**：检查是否覆盖以下异常场景类型
  - 网络异常
  - 服务端错误
  - 超时
  - 数据异常
  - 权限不足
  - 并发冲突
- **通过条件**：至少覆盖 3 种以上异常类型
- **未覆盖**：列出未涉及的异常类型

### 检查项 14：边界覆盖

- **检查方式**：检查是否存在边界值类用例
- **识别特征**：标题或步骤中包含「最大」「最小」「上限」「下限」「边界」等关键词
- **通过条件**：每个有明确约束条件的输入至少有 1 个边界用例

### 检查项 15：极端覆盖

- **检查方式**：检查是否存在极端类用例
- **识别特征**：标题或步骤中包含「大量」「高频」「特殊字符」「超长」等关键词
- **通过条件**：至少 1 个极端场景用例

## 五、质量评级

| 评级 | 条件 |
|-----|------|
| A | 格式 0 错误 + 内容 0 错误 + 覆盖 ≥ 12 项 |
| B | 格式 0 错误 + 内容 ≤ 1 错误 + 覆盖 ≥ 10 项 |
| C | 格式 0 错误 + 内容 ≤ 3 错误 + 覆盖 ≥ 8 项 |
| D | 存在格式错误 或 内容错误 > 3 |
| F | 文件无法解析 或 缺少核心字段 |

```
【格式检查】
  ✅ CSV 格式正确
  ✅ 字段完整
  ✅ 文件命名规范
  ⚠️  编码为 UTF-8 无 BOM

【内容检查】
  ✅ 用例编号连续
  ✅ 无重复用例
  ❌ {tc_id} 模块字段为空
  ✅ 优先级合法

【覆盖检查】
  ✅ 功能模块覆盖: {modules}
  ✅ 主流程覆盖
  ⚠️  缺少超时异常场景
  ✅ 边界覆盖
  ⚠️  缺少极端场景

【总体评价】
  质量评级: B
  格式: 3/4 通过
  内容: 5/6 通过
  覆盖: 4/5 通过
  建议: 补充超时异常场景和极端场景用例
```
