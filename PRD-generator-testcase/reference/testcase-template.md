# 测试用例规范模板

## 一、CSV 文件整体规范

### 1.1 文件编码

- 编码格式：**UTF-8 with BOM**
- 目的：确保中文字符在 Microsoft Excel 中正确显示
- 换行符：LF（\n）

### 1.2 字段定义

| 序号 | 字段名 | 必填 | 类型 | 说明 |
|-----|-------|------|------|------|
| 1 | 测试用例序号 | 是 | 字符串 | 格式：`tc_{序号}`，如 `tc_001` |
| 2 | 模块 | 是 | 字符串 | 功能模块名称，如「登录模块」「订单模块」 |
| 3 | 测试点 | 是 | 字符串 | 具体测试的功能点，如「账号密码登录」「手机号验证」 |
| 4 | 测试用例标题 | 是 | 字符串 | 简洁明确的用例标题，如「正确账号密码登录成功」 |
| 5 | 优先级 | 是 | 枚举 | 只能为 P0 / P1 / P2 / P3 / P4 |
| 6 | 操作步骤 | 是 | 字符串 | 有序操作步骤，步骤间用换行分隔 |
| 7 | 预期结果 | 是 | 字符串 | 明确可验证的预期结果 |
| 8 | 最终结果 | 否 | 字符串 | 实际执行结果，生成时留空 |
| 9 | 备注 | 否 | 字符串 | 补充说明，如前置条件、测试数据要求 |
| 10 | 测试人 | 否 | 字符串 | 执行人姓名，生成时留空 |

### 1.3 操作步骤编写规范

操作步骤需要：

1. 使用有序编号：`1. `、`2. `、`3. `
2. 每个步骤是一个原子操作
3. 步骤中包含具体的输入数据和操作对象
4. 步骤间在 CSV 中使用 `\n` 分隔

**示例：**

```
1. 打开登录页面
2. 在账号输入框输入"admin@test.com"
3. 在密码输入框输入"Test@123456"
4. 点击「登录」按钮
```

**反例（禁止）：**

```
打开页面后输入账号密码然后点登录看看行不行
```

### 1.4 预期结果编写规范

预期结果必须：

1. 可观察、可验证
2. 具体明确，不模糊
3. 包含页面元素变化描述
4. 包含提示信息文本（如有）

**正确示例：**

- 「页面跳转至首页，右上角显示用户昵称」
- 「提示"手机号格式不正确"，输入框标红，登录按钮置灰」
- 「列表新增一条记录，数据与输入一致」

**反例（禁止）：**

- 「功能正常」
- 「系统响应正确」
- 「操作成功」

## 二、用例标题编写规范

### 2.1 命名格式

`{条件/场景} + {操作} + {预期结果}`

**正确示例：**

- 「正确账号密码登录成功」
- 「错误密码登录失败并提示」
- 「搜索框输入为空时搜索按钮置灰」
- 「订单金额超过限额时提交失败」

### 2.2 标题长度

- 建议控制在 30 字以内
- 如确实需要更多描述，在备注栏补充

## 三、模块分类建议

建议按以下层级组织模块：

```
一级模块 > 二级模块 > 功能点
```

例如：

- 用户中心 > 登录注册 > 账号密码登录
- 交易系统 > 订单管理 > 创建订单
- 内容管理 > 文章发布 > 富文本编辑

在「模块」字段中填写一级模块，「测试点」字段中填写二级模块+功能点。

## 四、CSV 格式细节

### 4.1 特殊字符处理

| 字符 | 处理方式 |
|-----|---------|
| 逗号 `,` | 该字段使用双引号包裹 |
| 双引号 `"` | 转为两个双引号 `""` |
| 换行 `\n` | 使用双引号包裹，保留原始换行 |
| 中文标点 | 直接保留，无需转义 |
