# 优先级定义规则

## 一、优先级速查表

| 优先级 | 标签 | 定义 | 典型案例 |
|-------|-----|------|---------|
| P0 | 阻断 | 核心业务完全不可用 | 登录失败、支付失败、核心数据无法创建 |
| P1 | 严重 | 核心功能部分不可用或数据错误 | 密码错误无提示、订单金额计算错误、关键校验失效 |
| P2 | 一般 | 非核心功能异常 | 排序功能异常、筛选条件失效、页面样式错乱 |
| P3 | 轻微 | 体验问题 | 提示不够友好、按钮位置不顺手、加载动画缺失 |
| P4 | 建议 | 低优先级优化 | 日志信息优化、代码规范建议、低频操作优化 |

## 二、优先级判定逻辑

### 判定流程

```
是否导致核心业务流程无法走通？
  ├─ 是 → P0
  └─ 否 → 是否导致核心功能数据错误或关键校验失效？
            ├─ 是 → P1
            └─ 否 → 是否影响非核心功能正常使用？
                      ├─ 是 → P2
                      └─ 否 → 是否影响用户体验？
                                ├─ 是 → P3
                                └─ 否 → P4
```

### P0 判定标准（满足任一即为 P0）

- [ ] 核心业务流程中断（无法完成主要业务目标）
- [ ] 系统崩溃或不可访问
- [ ] 数据丢失或严重数据损坏
- [ ] 安全漏洞导致用户信息泄露
- [ ] 支付流程异常导致资金问题
- [ ] 核心功能接口完全不可用

### P1 判定标准（满足任一即为 P1）

- [ ] 核心功能部分场景不可用（但存在 workaround）
- [ ] 重要业务数据处理错误（如金额计算、状态判断）
- [ ] 关键校验规则失效（如权限校验、数据合规校验）
- [ ] 用户可感知的核心功能数据展示错误
- [ ] 影响大多数用户的高频功能异常

### P2 判定标准（满足任一即为 P2）

- [ ] 非核心功能异常（如排序、筛选、导出等辅助功能）
- [ ] 局部 UI 显示异常不影响操作
- [ ] 非关键字段校验缺失
- [ ] 操作后反馈信息不准确但操作本身生效
- [ ] 特定条件下偶现的异常

### P3 判定标准（满足任一即为 P3）

- [ ] 交互体验不顺畅（如多次点击才能完成、操作路径过长）
- [ ] 提示文案不清晰或缺失
- [ ] 页面加载速度慢但不影响功能
- [ ] 视觉样式与设计稿不符
- [ ] 无障碍访问问题

### P4 判定标准（满足任一即为 P4）

- [ ] 极端边界场景（正常使用难以触发）
- [ ] 低频使用路径的优化建议
- [ ] 非用户感知的内部实现优化
- [ ] 代码层面的优化点（不影响功能）

## 三、优先级分布建议

对于一般项目，建议优先级分布比例：

| 优先级 | 建议占比 | 说明 |
|-------|---------|------|
| P0 | 5-10% | 核心阻断级用例，必须先通过 |
| P1 | 15-25% | 重要功能用例，主要测试精力 |
| P2 | 30-40% | 一般功能用例，回归测试覆盖 |
| P3 | 15-25% | 体验优化用例，版本迭代中修复 |
| P4 | 5-10% | 低优先级建议，资源允许时执行 |

## 四、常见功能模块优先级参考

### 登录模块

| 场景 | 优先级 | 原因 |
|-----|-------|------|
| 正确账号密码登录成功 | P0 | 核心入口，阻断 |
| 错误密码提示 | P1 | 基础安全校验 |
| 登录状态过期处理 | P1 | 影响用户操作连续性 |
| 密码输入次数限制 | P2 | 安全增强功能 |
| 登录页加载动画 | P3 | 体验优化 |
| 100 条登录记录展示 | P4 | 极端场景 |

### 支付模块

| 场景 | 优先级 | 原因 |
|-----|-------|------|
| 正常支付流程 | P0 | 核心业务 |
| 支付回调处理 | P0 | 涉及资金安全 |
| 余额不足提示 | P1 | 核心校验 |
| 支付密码错误处理 | P1 | 安全校验 |
| 支付方式切换 | P2 | 非核心分支 |
| 支付页加载速度 | P3 | 体验优化 |

### 列表展示模块

| 场景 | 优先级 | 原因 |
|-----|-------|------|
| 默认列表数据加载 | P1 | 基础功能 |
| 分页功能 | P1 | 数据量大时必须 |
| 组合筛选功能 | P2 | 按需使用 |
| 排序功能 | P2 | 辅助功能 |
| 空数据提示文案 | P3 | 体验优化 |

### 内容发布模块

| 场景 | 优先级 | 原因 |
|-----|-------|------|
| 内容发布成功 | P0 | 核心业务 |
| 必填字段校验 | P1 | 数据完整性 |
| 草稿自动保存 | P2 | 辅助功能 |
| 发布按钮防重复点击 | P2 | 数据一致性 |
| 编辑器工具栏 UI | P3 | 体验优化 |

## 五、特殊规则

1. **安全相关场景自动 +1 级**：涉及权限、数据脱敏、SQL 注入、XSS 等安全测试的用例，优先级在原判定上提升一级（最高 P0）
2. **数据一致性场景自动 +1 级**：涉及金额、库存、积分等敏感数据的一致性校验，优先级在原判定上提升一级
3. **主链路不可降级**：涉及核心业务主链路的用例优先级不得低于 P1
4. **前置用例不降级**：如果某个 P2 用例是 P0/P1 用例的前置条件，则该用例也提升至 P1
